= Regression Test Infrastructure

Regression commands are mise tasks so the same commands run locally and in GitHub Actions.

== Running tests

[source,bash]
----
mise tasks                   # list tasks
mise run check:smoke         # fast subset
mise run check:unit          # unit tests
mise run check:integration   # integration tests
mise run check:artifacts     # generated artifacts
mise run check:all           # complete suite
mise run test:ruby:sorbet    # one named test
mise run test:ruby:udb-unit --test conditions # one matrix variant
----

The aggregate tasks are defined in `tools/dev/regression-aggregates.toml`.
Individual regression tasks are executable file tasks under
`tools/dev/regression-tasks/`.

== Adding a regression

1. Add an executable mise file task under `tools/dev/regression-tasks/`.
2. Give it a descriptive namespaced task name through its path.
3. Add it to the applicable `check:*` aggregates in
   `tools/dev/regression-aggregates.toml`.
4. Add it to `.github/workflows/regress.yml` when CI should run it.
5. Run `mise tasks validate` and the new task locally.

File tasks use mise `usage` declarations for matrix-like arguments. Keep setup or
artifact-upload steps that only make sense in GitHub Actions in the workflow; keep
the reusable test command in the mise task.

== Continuous integration

`.github/workflows/regress.yml` is maintained by hand. Jobs use the repository's
mise setup action and call the same named tasks available locally. Merge-queue-only
artifact jobs are guarded by event conditions. `regress-complete` remains the
required aggregate CI job.
