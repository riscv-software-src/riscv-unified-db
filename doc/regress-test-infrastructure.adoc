= Regression Test Infrastructure

Regression commands are mise tasks so the same commands run locally and in GitHub Actions.

== Running tests

[source,bash]
----
mise tasks                   # list tasks
mise run test                # default Python unit and specification tests
mise run check               # retained data, IDL, layout, fixture, and quality checks
mise run check:all           # complete suite
mise run test:slow:idl -- --config rv64 # one slow matrix variant
mise run test:cpp-hart -- --config rv64 # one native test
----

Task declarations are in `tools/dev/tasks.toml`; reusable implementation lives
in Python modules under `tools/dev/`.

== Adding a regression

1. Add a descriptive namespaced task to `tools/dev/tasks.toml`.
2. Put non-trivial reusable logic in an appropriate Python module under
   `tools/dev/`.
3. Add it to the applicable aggregate task.
4. Add a readable job or step to `.github/workflows/regress.yml` when CI should
   run it independently.
5. Confirm the task appears in `mise tasks`, then run it locally.

Tasks use mise `usage` declarations for arguments. Keep setup or artifact-upload
steps that only make sense in GitHub Actions in the workflow; keep reusable test
and generation commands in mise tasks.

== Continuous integration

`.github/workflows/regress.yml` is maintained by hand. Jobs use the repository's
mise setup action and call the same named tasks available locally. Merge-queue-only
artifact jobs are guarded by event conditions. `regress-complete` remains the
required aggregate CI job.
