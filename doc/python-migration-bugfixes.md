# Python migration bug fixes

This is the running record of confirmed defects in the Ruby implementation
that the Python migration intentionally corrects. An entry belongs here only
after the Ruby behavior has been reproduced or established by the full
differential corpus. Review defects found only in new Python code are fixed and
tested, but are not labeled as Ruby defects.

| # | Confirmed Ruby behavior | Python correction and regression |
| ---: | --- | --- |
| 1 | The overlay merge claims RFC 7386 behavior, but an object patch applied where the target member is absent or non-object is copied directly. For example, merging `{"a": 1}` with `{"a": {"drop": null, "keep": 2}}` produces `{"a": {"drop": null, "keep": 2}}`. | `merge_patch` implements RFC 7386: an object patch uses an empty object when its target is not an object, recursively removes `null` members, and does not mutate either input. Entry 40 also affects exception reachability across independently cloned symbol tables
with the same name. The standalone [`ruby_idl_passes_assignment_binding.rb`](../tests/python/ruby_idl_passes_assignment_binding.rb)
reproducer analyzes an unknown Boolean guard twice: Ruby returns masks 160 and 32,
although both contexts permit faults 5 and 7. The same stale `adue` binding suppresses
an implicit page-table write in the real `_`, `rv32`, and `rv64` `lw` and
`read_memory` observations (including both execution widths where applicable):
Ruby emits 8240/[4,5,13] instead of 8368/[4,5,7,13]. The guarded expected-side adapter
corrects only these eight exception observations, preserving the frozen corpus and all
other fields. Independent binding-ownership and scalar-specialization regressions
retain the implicit-write edge; no production mask override is introduced. This is
additional evidence of entry 40's root cause, not a new defect.
